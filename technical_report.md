# Технический отчёт: система прогнозирования академической успеваемости



## 1. Общее описание системы

Проект состоит из двух Python-скриптов, реализующих конвеер машинного обучения для прогнозирования академической успеваемости студентов российских вузов. Система предсказывает вероятность того, что студент сохранит "чистый академический результат" в следующем семестре, то есть завершит его без блокирующих оценок (тройки, двойки, незачёты, неявки) и без пересдач. Согласно правилам российского высшего образования, чистый результат в семестре N даёт право на стипендию, выплачиваемую в семестре N+1. Таким образом, модель выступает как система раннего предупреждения на один семестр вперёд.

Первый скрипт (`scholarship_predict_histgb.py`) - каноническая версия, работающая со всем массивом данных по студентам очной формы обучения. Второй скрипт (`scholarship_predict_histgb_bachelors_sem2_3.py`) - копия, работающая с предварительно отфильтрованным срезом: только бакалавры очной формы, только студенты, присутствующие одновременно во 2-м и 3-м семестрах (987 человек). Оба скрипта идентичны по логике; второй отличается лишь входным файлом данных и выходной папкой.

В качестве алгоритма используется `HistGradientBoostingClassifier` из scikit-learn - градиентный бустинг. Он поддерживает нативную обработку пропущенных значений (NaN), что критически важно для данных, в которых семестры с исключительно зачётными дисциплинами не имеют средних баллов.


## 2. Архитектура конвейера

Конвейер организован в пять последовательных этапов, каждый реализован отдельной функцией. Точка входа - функция `main()`, которая разбирает аргументы командной строки и последовательно вызывает все этапы.

**Этап 1 - Загрузка данных** (`load_data`): чтение xlsx-файла, первичная фильтрация и подготовка целевых колонок.

**Этап 2 - Конструирование признаков** (`build_features`): дедупликация записей, агрегация по дисциплинам, вычисление статистик на уровне (студент, семестр).

**Этап 3 - Построение обучающих пар** (`build_pairs`): создание переходов "семестр N -> семестр N+1" для каждого студента.

**Этап 4 - Обучение модели** (`train_model`): разделение данных, настройка и обучение HistGradientBoosting.

**Этап 5 - Оценка и сохранение** (`evaluate_and_save`): расчёт метрик, сравнение с бейзлайнами, сохранение артефактов.



## 3. Константы и словари

Скрипт определяет набор словарей и множеств, кодирующих правила.

`SEMESTER_MAP` преобразует текстовые названия семестров в числовой порядковый номер (от 1 до 10). `GRADE_MAP` переводит текстовые отметки в числовую шкалу: "Отлично" = 5, "Хорошо" = 4, "Удовлетворительно" = 3, "Неудовлетворительно" = 2, "Зачтено" = 4 (приравнивается к "хорошо" для числовых расчётов), "Не зачтено" и "Неявка" = 2.

Множество `SCHOLARSHIP_BLOCKING_GRADES` содержит четыре отметки, которые блокируют право на стипендию: "Удовлетворительно", "Неудовлетворительно", "Не зачтено" и "Неявка".

`PASS_FAIL_CONTROL_TYPES` и `PASS_FAIL_GRADES` определяют зачётные дисциплины, не вносящие вклад в средний балл (GPA). Основной критерий - вид контроля "Зачет"; текстовые отметки "Зачтено" / "Не зачтено" служат дополнительной проверкой.

Словарь `DEDUP_PRIORITY` задаёт приоритеты видов контроля для дедупликации: когда одна и та же дисциплина представлена несколькими строками (экзамен + курсовая работа), сохраняется запись с наименьшим приоритетом (экзамен = 0, зачет с оценкой = 1, курсовые = 2, зачет = 3). Это гарантирует, что при подсчёте доли пятёрок и троек используется оценка за основной вид контроля.

`KEPT_VEDOMOST_TYPES` перечисляет типы ведомостей, которые не удаляются из данных: "Основная", "Перезачет", "Пересдача", "Пересдача с комиссией". 

`RETAKE_VEDOMOST_TYPES` - подмножество двух последних, обозначающее пересдачи.

`CLASS_B_LABELS` определяет четырёхклассовую диагностическую разметку переходов: 1 = сохранил->сохранил, 2 = сохранил->провал (потеря стипендии, ключевой случай), 3 = провал->сохранил (восстановление), 4 = провал->провал.



## 4. Источники данных и схема

### 4.1. Основной датасет

Каноническая версия конвейера работает с файлом `ГОСТ Р 70946-2023-Приложение-8_sorted.xlsx`, содержащим построчные записи академической успеваемости студентов.

### 4.2. Срезовый датасет

Срезовая версия использует файл `output_bachelors_both_sem2_3_ochnaya.xlsx` - 18 524 строки в исходном xlsx. Схема полностью идентична основному файлу. Все константы канонического скрипта (`SEMESTER_MAP`, `GRADE_MAP`, `KEPT_VEDOMOST_TYPES`, `DEDUP_PRIORITY` и др.) применимы без изменений. Единственное отличие - предварительная фильтрация: это готовый набор переходов 2->3 без пропущенных строк.

### 4.3. Схема данных и неиспользуемые столбцы

Оба датасета содержат 17 столбцов. Конвейер берёт из них следующие: `ЗачетнаяКнижка` (идентификатор студента), `ПериодКонтроля` (текстовое название семестра), `ФормаОбучения`, `ТипВедомости`, `ВидКонтроля`, `Дисциплина`, `ИтоговаяОтметка` (текстовая итоговая оценка), `Пересдача` (балл по 100-балльной шкале за пересдачу), `Комиссия` (балл за комиссионную пересдачу).

Ряд столбцов намеренно не используется конвейером:

- `ПерваяАттестация`, `ВтораяАттестация`, `ТретьяАттестация` - промежуточные оценки преподавателя в течение семестра по 100-балльной шкале.
- `Экзамен` - 100-балльный экзаменационный балл.
- `КодПреподавателя` - идентификатор преподавателя.
- `УчебныйПлан` - код учебного плана.
- `УровеньПодготовки` - уровень образования (бакалавриат, магистратура).
- `ПересдачаДляДиплома` - флаг пересдачи для допуска к дипломной защите.

Целевая переменная `clean_record` вычисляется строго из `ИтоговаяОтметка` + `Пересдача` + `Комиссия` + `ТипВедомости`.



## 5. Этап 1: загрузка и очистка данных

Функция `load_data` выполняет следующие операции:

Чтение xlsx-файла. Преобразование столбца `ПериодКонтроля` в числовой номер семестра через `SEMESTER_MAP`; строки с нераспознанным семестром отбрасываются. Фильтрация по форме обучения: остаются только записи с `ФормаОбучения == "Очная"`. Фильтрация по типу ведомости: остаются только записи из `KEPT_VEDOMOST_TYPES`.

Далее выполняется дедупликация пересдач. Для каждой комбинации (студент, семестр, дисциплина) строится множество ключей, для которых существует запись типа "Основная". Пересдачные строки, дублирующие существующую "Основную" запись, удаляются. Это предотвращает двойной подсчёт оценок.

Создаются три производных столбца. `grade_num` - численная оценка через `GRADE_MAP`. `is_scholarship_blocking` - бинарный флаг, равный 1, если итоговая отметка входит в `SCHOLARSHIP_BLOCKING_GRADES`. `has_retake` - флаг пересдачи, равный 1, если балл по столбцу "Пересдача" или "Комиссия" больше нуля, либо итоговая отметка - "Неявка".

Особая обработка перезачётов: для записей типа "Перезачет" оба флага (`is_scholarship_blocking` и `has_retake`) принудительно обнуляются, поскольку перезачёт из предыдущего образования не может блокировать стипендию и не является пересдачей. При этом оценки перезачётов учитываются в GPA и в общем числе дисциплин.



## 6. Этап 2: конструирование признаков

Функция `build_features` превращает набор построчных записей (одна строка = один предмет у одного студента) в строки уровня (студент, семестр).

**Шаг 1: дисциплинарная агрегация.** Для каждой уникальной тройки (студент, дисциплина, семестр) вычисляются агрегаты: `disc_any_block` (была ли хотя бы одна блокирующая оценка), `disc_any_retake` (была ли пересдача), `disc_min_grade` (минимальная оценка). Это нужно, потому что одна дисциплина может быть представлена несколькими строками (экзамен + курсовая), и агрегат фиксирует "худший случай".

**Шаг 2: дедупликация.** Каждой строке назначается приоритет по виду контроля через `DEDUP_PRIORITY`. Данные сортируются по (студент, дисциплина, семестр, приоритет, оценка), после чего дубликаты удаляются с сохранением первой строки. Таким образом, для каждой дисциплины остаётся одна запись с наиболее значимым видом контроля.

После дедупликации обратно присоединяются дисциплинарные агрегаты: `is_scholarship_blocking` заменяется на `disc_any_block`, `has_retake` - на `disc_any_retake`, а `grade_num` берётся как минимум из текущей оценки и `disc_min_grade`. Это гарантирует, что даже если после дедупликации осталась строка с хорошей оценкой, в статистику попадёт худшая оценка по дисциплине.

**Шаг 3: разделение на оцениваемые и зачётные дисциплины.** Признак `is_pass_fail` устанавливается по виду контроля `Зачет` или по текстовым отметкам "Зачтено" / "Не зачтено". Дисциплины с оценками (не зачётные) формируют подмножество `df_graded`.

**Шаг 4: семестровая агрегация.** На уровне (студент, семестр) вычисляются следующие признаки:

- `n_subjects` - общее количество уникальных дисциплин.
- `n_blocks` - количество предметов с блокирующими оценками.
- `n_retakes` - количество предметов с пересдачами.
- `any_block` - бинарный флаг наличия хотя бы одной блокирующей оценки.
- `any_retake` - бинарный флаг наличия хотя бы одной пересдачи.
- `gpa_overall` - средний балл, рассчитанный только по оцениваемым (не зачётным) дисциплинам.
- `min_grade` - минимальная оценка по оцениваемым дисциплинам.
- `std_grade` - стандартное отклонение оценок.
- `share_5` - доля пятёрок среди оцениваемых дисциплин.
- `share_3` - доля троек среди оцениваемых дисциплин.
- `share_zachet` - доля зачётных дисциплин в общей нагрузке.

Доли `share_5` и `share_3` вычисляются по числовой оценке (`grade_num`), а не по текстовой отметке, чтобы исключить расхождения, вызванные заменой оценки на `disc_min_grade`.

**Шаг 5: определение целевой переменной.** Столбец `clean_record` устанавливается в 1, если у студента в данном семестре нет ни одной блокирующей оценки и ни одной пересдачи (`any_block == 0` и `any_retake == 0`).



## 7. Этап 3: построение обучающих пар

Функция `build_pairs` формирует обучающую выборку, в которой каждая строка - это переход между двумя последовательными семестрами одного студента.

Для каждого студента семестры упорядочиваются по номеру. Для каждой пары (семестр N, семестр N+1, строго следующий семестр), создаётся одна обучающая строка: признаки берутся из семестра N, а целевая переменная `target_clean_next_sem` - значение `clean_record` из семестра N+1. Непоследовательные семестры (например, 3->5 при отсутствии 4-го) пропускаются, поскольку признаки одного семестра не предназначены для предсказания на два шага вперёд.

Один студент может дать несколько пар за свою карьеру (2->3, 3->4, 4->5 и т.д.). В срезовой версии (бакалавры, семестры 2 и 3) каждый студент даёт ровно одну пару.

Дополнительно создаётся признак `had_clean_current_sem` - копия `clean_record` текущего семестра, если студент чист в текущем семестре, он с высокой вероятностью останется чистым в следующем.

Формируется диагностический четырёхклассовый столбец `class_B` через функцию `variant_b`: класс 1 (сохранил->сохранил), класс 2 (сохранил->провал), класс 3 (провал->сохранил), класс 4 (провал->провал). Этот столбец используется только в отчётности, не в обучении.



## 8. Этап 4: подготовка данных и обучение модели

### 8.1. Подготовка признаков

Функция `_prepare_features` формирует матрицу признаков `X` и вектор целевой переменной `y`. Из столбцов исключаются: идентификатор студента (`ЗачетнаяКнижка`), целевая переменная, номер целевого семестра, четырёхклассовая метка и текущий `clean_record`.

Значение NaN возникает в семестрах, состоящих исключительно из зачётных дисциплин, и является легитимным: заполнение нулём было бы некорректным, так как 0 не входит в шкалу оценок 2-5.

Итоговый набор признаков содержит 13 переменных: `sem_num`, `n_subjects`, `n_blocks`, `n_retakes`, `any_block`, `any_retake`, `gpa_overall`, `min_grade`, `std_grade`, `share_5`, `share_3`, `share_zachet`, `had_clean_current_sem`.

### 8.2. Разделение на обучающую и тестовую выборки

Функция `_split_by_students` реализует разбиение 80/20 на уровне студентов, а не на уровне строк. Все пары одного студента попадают целиком либо в обучающую, либо в тестовую выборку.

Используется фиксированный `random_state=42` для воспроизводимости результатов.

### 8.3. Обучение HistGradientBoosting

Перед обучением вычисляются веса примеров через `compute_sample_weight("balanced", y_train)`.

Гиперпараметры модели:

- `max_iter=1000` - максимальное число деревьев.
- `learning_rate=0.05` - скорость обучения.
- `max_depth=5` - максимальная глубина каждого дерева, для ограничения сложности модели.
- `min_samples_leaf=10` - минимальное число примеров в листе, для предотвращения переобучения на малых подгруппах.
- `l2_regularization=5.0` - ругуляризация весов в листьях.
- `early_stopping=True` - ранняя остановка.
- `validation_fraction=0.15` - 15% обучающей выборки выделяется для валидации ранней остановки.
- `n_iter_no_change=50` - обучение останавливается, если за 50 итераций метрика не улучшилась.
- `scoring="roc_auc"` - метрика ранней остановки - ROC-AUC.



## 9. Этап 5: бейзлайны, оценка и сохранение

### 9.1. Бейзлайны

Функция `_run_baselines` вычисляет пять простых правил для сравнения с моделью:

1. **Majority** - всегда предсказывать наиболее частый класс в обучающей выборке.
2. **Persistence** - предсказывать, что состояние следующего семестра будет таким же, как текущего (`had_clean_current_sem`).
3. **Rule no blocking** - предсказывать чистый результат, если нет блокирующих оценок и пересдач.
4. **GPA >= 4.0** - чистый результат, если средний балл не ниже 4.0.
5. **GPA >= 4.2** - чистый результат, если средний балл не ниже 4.2.

Для каждого бейзлайна рассчитываются Accuracy, F1 (macro) и ROC-AUC.

### 9.2. Метрики модели

На тестовой выборке вычисляются: общая точность (Accuracy), F1-мера (macro-усреднение), ROC-AUC по вероятностям. Строится матрица ошибок бинарной классификации и развёрнутый classification report (precision, recall, F1 для каждого класса).

### 9.3. Четырёхклассовый анализ

Бинарные предсказания модели комбинируются с наблюдаемым текущим состоянием (`had_clean_current_sem`) для получения четырёхклассовых предсказаний. Строится матрица 4x4 и вычисляется точность для каждого из четырёх классов переходов.

### 9.4. Подгрупповой анализ

Отдельно оцениваются две подгруппы: студенты с чистым текущим результатом (`had_clean=1`) и студенты с нечистым (`had_clean=0`). Для каждой подгруппы рассчитываются свои метрики и classification report. Это позволяет понять, насколько хорошо модель работает для "стабильных" и "нестабильных" студентов.

### 9.5. Выходные артефакты

Скрипт сохраняет следующие файлы:

- `predictions.csv` - построчные предсказания для тестовой выборки: идентификатор студента, номер семестра, вероятность хорошего результата, бинарное предсказание, фактический результат, четырёхклассовые метки, показатель риска (`risk_score = 1 - prob_clean`).
- `summary.md` - отчёт с таблицами метрик.
- `model_card.json` - карточка модели: тип, целевая переменная, список признаков, метрики, бейзлайны, посеместровая точность, гиперпараметры.



## 10. Различия между двумя скриптами

Второй скрипт (`scholarship_predict_histgb_bachelors_sem2_3.py`) является копией первого. Различия:

- Входной файл: `output_bachelors_both_sem2_3_ochnaya.xlsx` (предварительно отфильтрованный срез бакалавров, очная форма, семестры 2 и 3, 987 студентов).
- Каждый студент даёт ровно одну обучающую пару (семестр 2 -> семестр 3).

Вся остальная логика - константы, загрузка данных, конструирование признаков, обучение и расчёт метрик - идентична каноническому скрипту.
